# C++ 后台开发实习：顺序学习清单

更新：2026-09-20。补充 Linux 教程学习安排，并把端口实操放到网络基础之后。本版按你的最新要求，替代上一版按月份和课表安排的计划。只规定学什么、顺序、练习和验收，不规定每日或每周投入。

## 目标与执行规则

第一段实习的准备目标：C++ 后台／服务端开发实习生。工作对象是运行在服务器上的程序：接收请求、处理任务、访问数据、支持并发、定位错误与性能问题。找岗位时关注 C++ 后台开发、服务端研发、后端开发（接受 C++）等名称，并阅读实际职责。

这项选择基于你已有 C++ 与算法竞赛基础，方便尽快补齐工程能力；不代表 C++ 岗位在市场上必然更容易录用，也不把未来职业限定在一种语言。

学习顺序：开发工具 → 工程 C++ → 操作系统与并发 → 网络协议 → Linux 网络编程 → 后台项目第一版 → MySQL 与项目持久化 → Redis 基础 → 部署、测试与性能定位。形成可演示项目后即可开始投递；后续章节可以继续补，不必全部学完才申请。

执行方法：每阶段依次完成知识点和练习。能不照抄地完成验收、解释关键代码，再进入下一阶段。练习可以查文档，不要求记住所有接口参数。遇到细枝末节先记下，不以通读资料作为验收标准。

## 1. 开发工具：先学会构建、运行和调试

按顺序学习：

- [x] Linux 文件路径、目录、文件权限、标准输入输出、管道、重定向、环境变量。
- [x] 常用操作：cd、ls、mkdir、cp、mv、less、tail、grep／rg、find、chmod；能查帮助即可。
- [x] 进程查看：ps、top；了解正常终止程序与强制终止的区别。原条目中的 ss 端口实操移至第 4 阶段，已学内容可直接验收。
- [x] 编译流程：预处理、编译、汇编、链接；头文件与源文件、声明与定义、链接错误。
- [x] Git：init／clone、status、diff、add、commit、branch、switch、merge；处理一次简单冲突。
- [ ] CMake：可执行目标、库目标、include 路径、链接依赖、子目录、Debug／Release。
- [ ] GDB：断点、单步、查看变量、调用栈；编译器警告和调试符号。

练习：将一个熟悉的竞赛程序拆为 main.cpp、算法实现和头文件，用 CMake 构建并用 Git 记录修改，故意制造一次错误并用 GDB 定位。

验收：能从源码构建运行；知道编译错误、链接错误、运行时错误分别发生在哪；能定位报错位置和调用路径。

资料：[MIT Missing Semester](https://missing.csail.mit.edu/) 中的 Shell、命令行、版本控制相关内容；[CMake 官方教程](https://cmake.org/cmake/help/latest/guide/tutorial/index.html) 中可执行文件、库、链接与子目录部分。

Linux 入门主教材补充：[只学够用的 Linux：零基础最小入门教程](https://www.zouht.com/4399.html)。具体选读顺序、练习与验收见 [Linux 教程学习安排](Linux教程学习安排.md)。Linux 部分优先用这份中文教程学习，Missing Semester 按需补充，不要求同一内容重复通读。

当前衔接：保留上面已勾选的进度。先按补充安排自检基础，再补软件安装、环境配置、任务管理和文件打包；通过后继续 Git → CMake → GDB。教程中的网络操作和磁盘管理不作为进入 Git 的前置条件。

## 2. 工程 C++：从竞赛程序到可维护程序

默认使用 C++17，不需要先学习最新标准全部特性。熟悉的基础语法与算法容器用法可跳过复习。

按顺序学习：

- [ ] 指针／引用、const、作用域、存储期；栈对象与动态分配对象。
- [ ] 类、封装、构造／析构、成员初始化列表；组合、继承、虚函数、虚析构和多态。
- [ ] 拷贝构造／赋值、移动构造／赋值；左值／右值、std::move、Rule of Zero／Five。
- [ ] RAII、资源所有权、unique_ptr、shared_ptr、weak_ptr；循环引用和悬空指针。
- [ ] vector 扩容、迭代器失效、unordered_map 哈希与冲突、map 的有序性质；常用操作复杂度。
- [ ] 模板基础、lambda 捕获、std::function；注意引用捕获对象的生命周期。
- [ ] 错误处理、异常与析构、接口边界；按职责拆分模块，避免一个类承担全部功能。
- [ ] AddressSanitizer／UndefinedBehaviorSanitizer 的基本使用。

练习：实现一个小型文本统计工具，分出输入、计算、输出模块；再实现一个只管理单一文件资源的 RAII 包装，明确是否允许拷贝和移动。

验收：能解释每个对象由谁拥有、何时销毁；能判断该用值、引用还是智能指针；能定位一次越界或对象生命周期问题。

资料：[C++ Core Guidelines](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines) 的资源管理、类、错误处理部分作为实践参考。若类与拷贝基础薄弱，先补对应 C++ 入门教材内容，Guidelines 不替代入门教学。

暂缓：模板元编程、协程框架、手写 STL、复杂设计模式目录。

## 3. 操作系统与并发：理解程序怎样运行

按顺序学习：

- [ ] 程序、进程、线程；用户态／内核态、系统调用、上下文切换与调度基本概念。
- [ ] 虚拟地址空间、堆／栈、页表、分页、TLB、缺页；CPU 缓存和局部性的基本作用。
- [ ] 文件描述符、open／read／write／close；文件偏移、缓冲与持久化的区别，mmap 的用途。
- [ ] 进程间通信的基本用途：管道、共享内存、socket；不用全部深入实现。
- [ ] 并发共享状态、数据竞争、临界区、互斥锁、死锁的条件与避免方法。
- [ ] std::thread、join、mutex、lock_guard、unique_lock、condition_variable；条件变量配合谓词等待。
- [ ] atomic 的基本用途；理解单个操作原子不等于整个业务流程正确。首轮先用默认内存序。
- [ ] 有界队列、生产者消费者、固定工作线程、停止与退出流程。

练习：先写共享计数器并修复竞争；再写有界阻塞队列；最后组织成小型线程池，支持提交任务、处理队列满、结束时唤醒等待线程并 join。

验收：解释共享数据由哪把锁保护；任务异常、队列满、停止时如何处理；能指出锁范围过大和持锁等待可能造成的问题。

资料：[OSTEP](https://pages.cs.wisc.edu/~remzi/OSTEP/)。推荐顺序：Processes／Process API → Address Spaces／Address Translation／Paging／TLB → Concurrency and Threads／Locks／Condition Variables／Concurrency Bugs → Files and Directories。按标题找章节，不需要通读。

暂缓：完整内核、复杂调度器、无锁队列和深入 memory_order。

## 4. 计算机网络：先理解协议，再写网络程序

按顺序学习：

- [ ] 分层、封装，IP 地址、端口、子网与路由的基本作用；ARP、DNS、NAT 的用途。
- [ ] TCP 与 UDP；TCP 字节流为什么没有应用消息边界。
- [ ] 建连与关闭、半关闭、TIME_WAIT；确认与重传、滑动窗口、流量控制与拥塞控制的区别。
- [ ] HTTP 方法、路径、请求头／响应头、状态码、请求体、长连接；JSON 与接口约定。
- [ ] HTTPS、证书与 TLS 分别解决什么问题；Cookie、Session、Token 的基本用途。
- [ ] HTTP/2 的多路复用概念；首轮不深入 HTTP/3 和 TLS 密码学细节。
- [ ] 理解 IP、端口、TCP 后，用 ss 查看自己实验程序的监听端口和连接；理解 HTTP 后练 curl；需要远程环境时选读 Linux 教程 1.10 并练 SSH／SCP。

练习：用 curl 查看请求和响应；抓一次自己测试服务的网络包，观察连接建立和数据传输。HTTPS 的应用内容被加密，不把看不到明文当作抓包失败。

验收：能讲清一次 HTTP 请求的主要路径；区分 DNS 查询、TCP 连接与 HTTP 交互；解释为什么应用程序需要定义消息边界。

资料：以学校计网教材或一本入门教材的应用层、传输层内容为主；接下来的 socket 实践使用 [Beej 网络编程指南](https://beej.us/guide/bgnet/html/split/)。

## 5. Linux 网络编程：做小实验理解服务器

按顺序学习：

- [ ] socket、bind、listen、accept、connect、send／recv、close／shutdown。
- [ ] 返回值、errno、EOF、EINTR；短读短写、接收缓冲和发送缓冲。
- [ ] 定长、分隔符、长度前缀三种消息边界方式；本练习选择长度前缀。
- [ ] 阻塞／非阻塞、EAGAIN；I/O 多路复用为什么有用，select／poll 的基本模型。
- [ ] epoll_create1／epoll_ctl／epoll_wait；先做 LT，再理解 ET 与非阻塞读写。
- [ ] 连接状态、输入输出缓冲、部分发送、断开清理；Reactor 的职责划分。

练习一：单连接 TCP echo 客户端与服务端，能处理分段到达的数据。

练习二：基于 epoll LT 扩展为多连接 echo，处理部分发送与客户端断开；保留独立小工程。不要直接扩张为完整网络框架。

验收：两个客户端能同时连接；应用消息被分多次发送仍正确；一个客户端断开不会使整个服务退出；说明 epoll 处理的是就绪通知，业务计算由谁执行仍需要设计。

资料：[Beej 指南](https://beej.us/guide/bgnet/html/split/) 的系统调用、客户端／服务端、阻塞、多路复用、部分发送和消息封装部分；[epoll Linux 手册](https://man7.org/linux/man-pages/man7/epoll.7.html)。

暂缓：高性能网络库全量复刻、多 Reactor、io_uring。

## 6. 主项目第一版：C++ 异步任务处理服务

沿用前面做过的文本统计与线程池，不再另找一个庞大项目。

学习与实现顺序：

- [ ] 写接口约定：提交文本统计任务、返回 ID、查询状态与结果。
- [ ] 使用成熟 HTTP 库接收请求；本路线默认选 cpp-httplib，JSON 库按需引入。
- [ ] 划分接口层、任务管理、计算模块、存储接口；通过清晰职责组织代码。
- [ ] 接入自己的有界任务队列与固定工作线程。明确 HTTP 库自身线程与任务执行线程的关系。
- [ ] 定义 queued／running／succeeded／failed 状态及允许的转换。
- [ ] 参数和输入大小校验、非法请求、任务不存在、队列满、计算异常的反馈。
- [ ] 增加配置、请求／任务 ID、日志和关键测试；第一版先内存保存任务。

验收：他人按 README 能从源码构建运行；提交任务后能查询到结果；错误输入不会导致服务崩溃；能解释从请求到执行完成的完整路径。

资料：[cpp-httplib 项目文档](https://github.com/yhirose/cpp-httplib)。网络实验和主项目分开；使用此库时不能在简历中将其内部网络能力描述成自己实现的 epoll 框架。

## 7. MySQL：会用，再理解索引和事务

按顺序学习：

- [ ] 关系表、字段类型、主键、唯一约束、非空、外键的用途；基础表设计与常见规范化思想。
- [ ] 建表、增删改查、WHERE、ORDER BY、LIMIT、GROUP BY、HAVING、JOIN；NULL 的处理。
- [ ] C++ 数据库访问、参数化查询、连接生命周期；SQL 注入原因；凭据通过配置传入。
- [ ] 索引与 B+ 树、InnoDB 聚簇索引／二级索引、回表、覆盖索引、联合索引与最左前缀。
- [ ] EXPLAIN：观察是否使用索引和扫描代价；索引的查询收益与写入成本。
- [ ] 事务、ACID、隔离级别、常见读写异常、MVCC 与 Read View 的基本作用。
- [ ] 行锁、间隙锁的用途、死锁与重试；具体行为结合 InnoDB 和隔离级别理解。
- [ ] undo、redo、binlog 的区别；连接池的用途，不要求自己造通用连接池。

项目扩展：保存任务与结果；设计查询所需的索引；说明事务边界；分析任务在“已入库但未入队”“执行后未保存结果”时退出的行为。先明确保证，再实现恢复。

验收：重启服务后能查已完成结果；能用两条数据库连接演示一次锁等待或隔离现象；解释项目某个索引为什么存在，以及哪个流程需要事务。

资料：[MySQL 官方入门教程](https://dev.mysql.com/doc/refman/8.4/en/tutorial.html)，之后按需读 [索引优化](https://dev.mysql.com/doc/refman/8.4/en/optimization-indexes.html) 和 InnoDB 相关章节。

到这里，如果项目可演示、基础知识能讲清，已经可以开始投递匹配岗位；不用等后面所有内容完成。

## 8. Redis：补缓存基础，先做独立实验

按顺序学习：

- [ ] 内存键值数据库的用途；String、Hash、List、Set、ZSet 的操作和典型使用场景。
- [ ] TTL、过期、内存淘汰策略；过期和淘汰的区别。
- [ ] Cache Aside：读缓存、查数据库、回填；更新数据库与删除缓存，以及可能的一致性窗口。
- [ ] 缓存穿透／击穿／雪崩的触发条件与常见处理；热点和缓存命中率。
- [ ] RDB／AOF 的基本差异；了解复制、Sentinel、Cluster 分别解决什么问题。

练习：做一个小查询缓存实验，对比命中、未命中、过期、数据库更新、Redis 不可用时的行为。默认先缓存已完成且不再变化的结果，减少可变状态的一致性复杂度。

验收：解释什么适合缓存、为什么设过期时间、缓存不可用时怎样处理。测量有收益且复杂度值得时再合并到主项目；否则保留独立实验并如实记录。

资料：[Redis 官方入门](https://redis.io/docs/latest/develop/get-started/)。暂缓 Redis 源码、自制分布式锁和集群部署。

## 9. 部署、测试与性能定位：让项目可交付

按顺序学习：

- [ ] 单元测试、接口／集成测试的区别；围绕正常路径、非法输入、并发、失败和退出设计测试。
- [ ] 构建脚本与自动测试；日志级别、任务 ID、配置管理；不把密码放进仓库。
- [ ] Docker 镜像与容器、Dockerfile、端口映射、数据卷、环境变量、Compose；理解数据库容器数据持久化。
- [ ] 超时、有限重试、幂等、队列上限、过载保护与优雅退出；在项目中实现最相关的两个故障场景。
- [ ] CPU／内存／磁盘／网络基本排查；top、ss、日志、GDB，再按问题使用 strace、perf 和 Sanitizer。
- [ ] 吞吐、并发、延迟分位数、错误率；固定环境与负载后做基线，再修改一个因素比较。

验收：别人按文档能启动服务和数据库；有测试、架构说明、压测记录及至少两篇故障定位记录；能说明已验证和未验证的范围。QPS 和“提升百分比”只写真实可复现测量值，异步任务应区分提交响应耗时与任务完成耗时。

资料：[Docker 官方入门](https://docs.docker.com/get-started/)。首轮没有必要上 Kubernetes。

## 10. 在开始投递后补：分布式基础概念

顺序：单体与多服务的区别 → RPC／序列化／超时 → 负载均衡与服务发现 → 重试与幂等 → 消息队列、确认和重复消费 → 复制、分片、故障切换 → 一致性与 CAP 的适用语境。

学习目标：能说明为什么需要这些机制、引入了什么代价。第一轮不实现 Raft、不做分布式数据库，不同时部署整套微服务组件。

练习：画出主项目扩为两个服务实例后的结构，逐一说明内存任务状态、共享数据库、重复请求与故障恢复会遇到什么问题。概念图中的能力不能写成已实现成果。

## 全程保留的面试能力

- 在已有算法训练里练常见题的清晰表达、边界与复杂度，不新增一套高强度刷题计划。
- 每完成一个模块，留下“遇到什么问题—怎样定位—为什么选这个方案—如何验证”的记录。
- 练习三分钟介绍项目，十分钟解释一条完整请求路径，以及一次失败场景。
- 每项简历技能应能对应到代码、实验或准确解释；遇到不会的问题可以说明边界。
