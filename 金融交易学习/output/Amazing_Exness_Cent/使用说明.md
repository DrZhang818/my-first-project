# Amazing 3.1：Exness XAUUSDc 美分账户兼容修正版

依据：用户提供的 Amazing 3.1 MQ4 源码、2026-09-18 当天本机 MT4 的 Journal / Experts 日志、当前 XAUUSDc M1 图表保存参数。用户确认券商 Exness、账户单位 USC。

## 已确认的问题

- Journal 反复显示挂单失败 `Invalid S/L or T/P`；当时订单 SL/TP 都是 0，这类错误同样可以表示挂单价离市场价格太近。原始首单距离 30 points，三位黄金报价下仅为 0.030 美元价格变化。未取得实时合约规格，尚不能区分全部拒单是静态限制、动态限制还是报价移动。
- 当前保存的 MaxSpread 已经是 400；源码默认值 32 不是当前这批拒单的已确认原因。截图的 260 是 points，而非标准外汇意义的 pips。
- Experts 日志最后记录自动交易被关闭。关闭状态与服务器拒单是两个问题。
- 原始日志没有输出 GetLastError 编号，无法从“开单失败”四个字定位问题。

## 修复内容

1. 初始挂单与追踪挂单统一使用动态最小距离，提交前刷新报价，按实际 tick size 向远离市场方向取整；报价移动导致价格不合法时等待下次重新计算。
2. 校验最小手数、手数步长、最大手数和可用保证金；对合法范围内的手数向下取整，不自动把小于最小手数的请求放大。
3. 发送前重新统计现有持仓与挂单，防止同一 tick 两方向同时提交突破数量或总手数上限，并防止重复同方向挂单。
4. 修改挂单前检查冻结距离，避免紧贴市价重复修改。
5. 输出错误编号、报价、距离、手数等诊断。服务器超时后延长等待，之后仍先检查已有挂单。
6. 停止提示区分自动交易、权限、点差和订单数量等原因。
7. 初始化原源码中编译器指出的未初始化分支及重试变量。

保留原来的双向挂单、仓位管理和复杂平仓策略；本次不是完整策略审计。距离增大、固定手数和订单上限会改变历史交易表现。

## 加载方法

1. 在自动交易关闭状态下，确认旧 Amazing 没有遗留持仓和挂单，然后从 XAUUSDc 图表移除旧 Amazing。若有旧单，不要同时挂两个同 Magic EA。
2. 在导航器“专家顾问”上刷新，找到 Amazing31_Exness_Cent_Fix，挂到 XAUUSDc M1。程序文件需位于当前终端数据目录的 MQL4/Experts。
3. 输入参数 → 加载 → 选择 XAUUSDc_USC_Diagnostic.set。确认单位 USC、三位报价、金额预算及合约规格。可以先在策略测试器或独立模拟环境验证行为。
4. 是否开启实时自动交易由用户自行决定；本次修改没有启用交易、没有替换当前图表上的 EA，也没有发送测试订单。
5. 在 Experts 中查看 `[Amazing specs]` 和 `[Amazing broker check]`。如仍为 error=130，保留完整该行与对应 Journal 信息，核对券商动态限制；不要改成市价单来掩盖问题。PendingFloorPoints 可进一步测试 1500 或 2000，但这会改变入场位置。

止损是 EA 运行时执行的金额退出，不是下到服务器的硬止损，断线、关闭自动交易、停止终端、跳空或拒单都可能使实际损失超出阈值。StopAfterLoss 的暂停状态只在本次运行内保存；切换周期、修改输入、重新挂载或重启可能复位。现有挂单不会仅因高点差或达到 MaxLoss 自动撤销。
